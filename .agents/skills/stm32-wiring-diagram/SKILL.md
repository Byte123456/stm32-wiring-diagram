# STM32 接线图 / 原理图生成

用项目自带的 `wirelib.py` 把电路画成 SVG。这套库是为了解决"AI 直接吐网表或 ASCII 图
画不好"这个问题：它把常用器件做成**符号函数**，把排版交给**坐标 + 自检器**，
而不是让模型凭空描述电路。

## 核心资产

| 文件 | 作用 |
|---|---|
| `references/quickref.md` | **接口速查（自动生成）—— 画图先读这一页，不必读源码** |
| `references/wirelib-api.md` | 补充 API：基础图元、配色常量、`Box`、`marker`（自绘器件时看） |
| `wirelib.py`（仓库根） | 器件符号库 + 画布 API + 两个自检器 + 配置读取器 |
| `scripts/check_svg.py` | **排版**体检门槛（调 `verify()`，可选出 PNG） |
| `scripts/check_net.py` | **电气**体检门槛（调 `analyze()`，查短路/旁路/穿体/悬空） |
| `scripts/measure_symbols.py` | 符号尺寸标定，改了符号几何后跑 |
| `scripts/gen_quickref.py` | 生成 quickref（改了符号后重跑，否则 selftest 会失败） |

新工程的脚本放在**工程自己的目录**里（如 `myproj/wire_diagram.py`），
通过 `sys.path.insert(0, "..")` 导入 `wirelib`（仓库根下有 `wirelib.py`）。

## 产物放哪里

**图必须和它描述的工程放在一起，放在工程目录下。** 别丢到临时目录或仓库根：

| 产物 | 命名 | 位置 |
|---|---|---|
| 场景接线图 | `wiring_<场景>.svg` | 工程目录 |
| 完整原理图 | `schematic_full.svg` | 工程目录 |
| 生成脚本 | `wire_diagram.py` / `schematic.py` | 工程目录 |
| 渲染自检用的 PNG | `_<名字>_check.png` | 工程目录（下划线开头，属临时产物） |

`Doc.save()` 传相对路径时以**脚本所在目录**为基准，并自动建目录 —— 所以脚本里
直接写 `d.save("wiring_led.svg")` 就会落在工程目录，不用拼 `os.path.dirname`。
（老脚本里那种 `os.path.join(OUT_DIR, ...)` 写法也完全可以，结果一样。）

## 标准流程

### 0. 先读接口速查页（不是源码）

```
references/quickref.md
```

**画图只需要这一页**：符号签名、端子坐标、包围盒、两个检查器怎么调、电气陷阱。
`wirelib.py` 只有在**要新增/修改符号本身**、或调试内部实现时才需要打开。

这一页是**从代码反射生成**的，所有坐标都是当场实测值 —— 所以它不会和实现漂移
（改了符号没重跑生成器的话，`selftest.py` 会失败）。

### 1. 先读配置，不要手抄

引脚写错是这类图最严重的错误——照着接能烧片子。**永远从源码读，不要凭记忆填**：

```python
import sys; sys.path.insert(0, "<仓库根>")   # 含 wirelib.py 的那一层
from wirelib import read_config
cfg = read_config("myproj")                # 工程目录
print(cfg["pins"])      # {'LED_R': ('A0','GPIOA'), 'KEY_SPEED': ('B12','GPIOB'), ...}
print(cfg["hse"])       # 8000000
```

`read_config` 读三个来源：`Core/Inc/main.h`（引脚宏）、`.ioc`（工具链/分频）、
`stm32f1xx_hal_conf.h`（HSE 真实值，最权威）。

### 2. 确认电气极性

**画之前必须确认两件事，画错了照着接就不工作：**

- **LED 方向**：`direction=1` 阳极在左，`-1` 阳极在右。
  灌电流（引脚→电阻→阴极）阳极朝电源；拉电流（引脚→阳极→阴极→电阻→地）阳极朝引脚。
- **驱动极性**：三极管驱动是**反相**的（IO 高→导通→亮）；直连电阻是**同相**的
  （IO 低→灌电流→亮）。同一个"共阳"接法，用三极管和用直连电阻**极性相反**，
  不能共用一句"低电平点亮"。

读 `main.c` 里的 `LED_ON_LEVEL` 宏，以及 `MX_GPIO_Init` 里的 `GPIO_MODE_*`，
确认实际是推挽还是开漏、高有效还是低有效。**如果源码注释和实际配置矛盾，以配置为准，
并在图里指出这个矛盾**（实测踩过：源码注释写"三极管或限流电阻都低电平亮"，
但三极管是反相的）。

### 3. 写生成脚本

```python
import os, sys
sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
from wirelib import *

d = Doc("标题", "副标题")
mcu_svg, ends = mcu_block(90, 150, 190, 400, "STM32F103C8T6",
                          pins_right=[("PA0", 30), ("PA1", 64)])
d.add(mcu_svg)
y = 180
d.wire(ends["PA0"], (400, y), w=2)        # 从引脚端点开始接, 不要手算坐标
d.add(resistor(500, y, label="1K"))
d.add(led(650, y, direction=-1, label="LED1"))
d.notebox(40, 700, 1100, [("① 说明文字", "n")], title="要点：", style="info")
d.save(os.path.join(os.path.dirname(os.path.abspath(__file__)), "wiring4.svg"))
```

`mcu_block` 返回的 `ends` 是**引脚引线的外侧端点**——后续导线一律从这里起笔，
不要自己加减坐标，否则会差出十几像素。同理，其他元件的接线端点用
`terminals()` 或符号返回值取，**别手填偏移**（见 `quickref.md` 的端子表）。

> **脚本没跑完就不要看产物。** `save()` 会立刻写盘；如果脚本在 `save()` 之后
> 才崩（或崩在中间），磁盘上留的是**上一次的旧图**。先确认脚本零报错，
> 再去读 SVG / 渲染 PNG，否则会对着一张过期的图下判断。

### 4. 必须自检（不可跳过）

```python
from wirelib import verify
n = verify("wiring4.svg")     # 打印问题, 返回问题数
```

检测**五类**问题 —— 前三类是排版，后两类是"图上缺东西"，最容易漏：

1. **文字互相重叠**
2. **文字压在长导线上**
3. **平行水平导线间距过近**（会被误读成"连接"）
4. **器件/说明框超出画布** —— 超出部分会被渲染器**直接裁掉**，图上少画一块，
   而空白边被裁掉时肉眼根本看不出来。这是最隐蔽的一类。
5. **器件与器件重叠** —— 两个符号画在了同一个位置

包围盒是**自动登记**的：`led`/`resistor`/`npn` 等符号返回的 SVG 外层带
`data-sym` 标记，`Doc.add()` 认出来就按标定尺寸登记。**所以已有的画图脚本
一行都不用改**，重跑一遍就自动受第 4、5 类保护。

**`verify` 返回非 0 就必须修，不要交付。**

**报告里已经带了改法，照着做即可**，不要自己重新推「该挪多少」：

```
[器件重叠] 40x30px  R1 <-> L1  → 垂直分开 ≥38px（把 R1 上移到 y≤247, 或把 L1 下移到 y≥353）
[超出画布] 右越界 18px          → 画布改成 w=818, h=618
[水平线过近] y=500 与 y=510 → 拉开到 ≥18px（把 y=510 那组下移 8px）
[文字压竖线] x=232 "33K"       → 文字左移 Npx (或右移 Mpx)
```

电气门同样带建议：

```
[悬空] Q1.c 差 13.0px        → 把该引线端点移到 y=498.0
[旁路] 1.5K 两端同网          → 竖线 x=300 纵穿本体, 改成从上下边缘起笔
[穿体] ...                    → 该竖线应止于 y=313.0 或从 y=355.0 起笔
```

**这能把「跑→看→想→改→再跑」压成「跑→照做→再跑」**，是省时间的关键。

它比肉眼可靠：早先一批图里"PA10/PA12"的标签正好压在导线上，
渲染成 PNG 时因为文字小、看着不刺眼很容易放过，`verify` 一次就抓出来了。
第 4 类检查上线时还当场抓到一处说明框下缘超出画布 4px。

或者直接用命令行：

```bash
python .agents/skills/stm32-wiring-diagram/scripts/check_svg.py "myproj/*.svg"
python .agents/skills/stm32-wiring-diagram/scripts/check_svg.py --png "myproj/*.svg"
```

退出码 0 = 干净。

### 5. 必须做电气自检（不可跳过）

**这是和排版自检完全独立的一道门，两道门都要过。**

```bash
python .agents/skills/stm32-wiring-diagram/scripts/check_net.py "myproj/*.svg"
```

它把图还原成网表、做连通性分析（**端点相接** + junction 才算连接），
共查**八类**：短路 / 旁路 / 穿体 / 悬空 / 接错 / 畸形线段 / 飘端子 / 孤标签。
每类的含义与后果见 `quickref.md` 第 4 节 —— **不要在这里另记一份**，
工具的类别名会随版本增加，摘要必然过期。

### ⚠️ 两道门各查什么、各不查什么

**排版门**（`verify()`）查七类：文字重叠 / 文字压线 / 平行水平线过近 / **平行竖线过近** /
**器件超出画布** / **器件互相重叠** / **文字超出画布**。

**电气门**（`analyze()`）查八类，见上。

两道门**都查不出**：

- **极性/方向画反** —— LED 阳极接到地、电解电容正负极反、二极管方向反。
  这些图两根线都接在正确端子上，连通性完美，全部检查返回 0。→ 下一步人工核对。
- **没 `declare()` 的自绘器件** —— 对检查器完全不可见（不是「查了没问题」，
  是「压根没看」）。
- **`declare()` 里的端子坐标画在哪儿** —— `terminals` 是**你手填的绝对坐标**，
  与符号内部的绘制代码之间没有任何一致性约束。你声明端子在哪，检查器就认为
  它在哪。**如果声明的位置和实际画出来的图形对不上，门禁查不出** ——
  有 `[飘端子]` 一类兜底（见下），但只抓「端子离开图形」这一种。
- **连着的东西对不对** —— 图可能**忠实实现了错误的意图**。
- **参数取值** —— 静态工作点、增益、元件数值。

**关于 `[飘端子]`**：自绘符号声明的端子若落在**自己画出的图形之外**，
电气门会报 `[飘端子]`。这是实测踩到的坑 —— 继电器线圈声明端子跨 `cx±38`，
但画弧的代码只跨 `cx±21`，两个端子各悬在图形外 17px。**连通性完美**
（导线确实接在声明的端点上），但图上看着像「线圈两端没接线」。
改动自绘符号后务必看一眼有没有这一类。

**关键推论**：`verify()` 返回 0 ≠ 电路是对的，渲染图看着干净 ≠ 电路是对的。
**「用肉眼看一遍确认没有电气错误」是无效手段** —— 短路和旁路在图上就是一根
普通直线，线条笔直、不压字不重叠，人眼和排版门都给满分。要么跑 `check_net.py`，
要么明确承认这块没查。

### 所以这一步必须人工做：核对**方向性**器件

跑完门禁后，**逐个确认下面这些器件的方向**：

| 器件 | 该确认什么 |
|---|---|
| LED / 普通二极管 | 阳极朝**高电位**侧。灌电流：阳极朝电源；拉电流：阳极朝引脚 |
| 续流二极管 | **反并联**在感性负载两端：阴极接电源侧，阳极接开关器件侧 |
| 电解电容 | 正极朝**高电位**侧（射极旁路电容正极朝射极） |
| 三极管 | NPN 还是 PNP？c/e 有没有接反 |
| 稳压二极管 | 阴极朝**高电位**（反接才稳压） |
| 光敏/光电二极管 | 通常**反偏**接法（阴极朝电源） |
| 电源/地符号 | `vcc` 接点朝下、`ground` 接点朝上 |

**怎么核对最省力**：用 `check_net.py --show-nets` 打出网表，看每个方向性
器件**两个端子各落在哪个网**，再按上表判断：

```
网1: ['GND', 'led.k', ...]          ← 阴极在地 → 对(灌电流)
网9: ['led.a', 'resistor@1329.l']   ← 阳极经电阻到电源侧 → 对
网11: ['D2.k', 'K1线圈.t', '+5V']   ← 续流管阴极在电源侧 → 对
```

这一步没有工具能完全替你做 —— 除非给自绘器件写 `declare(expect=...)`
（见下），但**内置的 `led`/`capacitor` 目前也只能靠人看**。

### 自绘器件必须 `declare()` —— 否则检查器对它完全瞎

`analyze()` 只认识 `wirelib` 里注册过的符号。**你自己拼的元器件
（继电器线圈、触点、续流管、光敏管、MOS、传感器模块……）它根本看不见** ——
不是"查了没问题"，是"压根没看"。这类器件接错能大摇大摆通过电气门。

用 `declare()` 声明端子、本体和期望连接：

```python
from wirelib import declare

coil_svg, coil = my_coil(640, 290)      # 自绘符号, 自己知道端子在哪
d.add(declare(coil_svg, "K1线圈",
              terminals={"t": (640, 268), "b": (640, 312)},   # 绝对坐标
              body=(617, 268, 663, 312),                      # 本体矩形
              expect={"b": "npn.c"}))                         # 该端应在哪个网

d.add(declare(d2_svg, "D2续流",
              terminals={"k": (550, 246), "a": (550, 272)},
              body=(537, 246, 563, 272),
              expect={"k": "+5V", "a": "K1线圈.b"}))   # 反并联在线圈两端
```

- `terminals` / `body` 是**绝对坐标**，与内置符号的 `terminals()` 同义。
  ⚠️ **这两个是你手填的，没有任何东西保证它们和符号画出来的图形一致** ——
  内置符号有 `measure_symbols.py` 校准，自绘符号没有。所以端子要落在**你自己
  画的图形上**，否则电气门会报 `[飘端子]`（端子悬在图形外，导线接上了但看着
  像没接线）。改完符号的绘制代码，记得把 `terminals` 一起改。
- `expect` 是**唯一能抓住"接到错节点"的手段**：接错节点时端子照样
  "接上了导线"，短路/旁路/穿体/悬空**全都不报**，只有把实际网络与期望
  网络比一次才发现。报错形如
  `[接错] D2续流.a 声明应与 K1线圈.b 同网, 实际却在 [...]`。
- 目标名可写电源名（`"+5V"`）或另一个器件的端子（`"K1线圈.b"`、`"npn.c"`）。
- 没声明的自绘符号会被忽略（与从前行为一致），不会让既有脚本报错。

**实测价值**：`expect` 上线时，在本技能自己的测试电路里抓出一处
**前四类全漏掉**的真实缺陷 —— 续流管与继电器线圈那一整块**没接到 +5V**
（电源母线画在 y=122，而 `vcc` 符号接点在 y=120，差 2px）。

### 6. 渲染确认（仅用于看**布局**）

```bash
python .agents/skills/stm32-wiring-diagram/scripts/check_svg.py --png "myproj/*.svg"
```

然后用 Read 工具看图。**注意 `svglib` 渲染时中文显示成方块**（它缺 CJK 字体），
这是渲染器的限制，**SVG 本身没问题**，用浏览器打开是正常的。所以别因为看到方块
就去"修"字体。

这一步**只看布局**：器件是否成排、走线是否交叉、标注是否错位。
**不要指望靠它发现电气错误**（见上）。


## 先判断电路形状，再选工具

**画之前先看电路是什么形状** —— 三类结构各有对应工具，选错了就得手算坐标：

| 电路形状 | 用什么 | 例子 |
|---|---|---|
| 串联支路（一进一出） | `chain()` | 引脚 → 电阻 → LED → GND |
| 分支节点（一节点接 3~4 路） | `bus_net()` | 分压点、集电极节点、电源母线 |
| 纯连接关系已知，不想碰坐标 | `net2svg()` | 单主干电路，一次性生成 |
| 自绘器件（继电器/光敏管/MOS） | 先 `register_symbol()`，再配合 `declare()` | — |

```python
# 分支节点: 一根竖直母线, 各支路按方向挂出去
bus_net(d, cx=400, y0=200, y1=700, label="A", branches=[
    ("D1", "up",   0.0,  "led",      dict(s=13, direction=1), "光敏"),
    ("R1", "down", 0.35, "resistor", dict(w=42, h=15), "10K"),
    ("RV", "down", 0.75, "resistor", dict(w=42, h=15), "10K"),
])
```

**两条硬约束**（都踩过）：

1. **元件本体绝不能压在母线上** —— 母线是连续竖线，骑在它上面的元件会被纵穿
   （= 旁路）。`bus_net()` 会自动把元件横放在侧面、用引线拐回来；你也别手写
   "竖放电阻直接挂母线"。
2. **同一母线同侧挂多路时，引出线会共线。** 两路都从右端往下走，上面那路的
   竖线必然穿过下面那路的本体 —— 上路要往更外侧绕。

**母线之间、母线到 MCU 的连线仍需自己画**（`d.add(line(...))`），此时用
`bus_net()` 返回的 `ends`/`terms` 取坐标，不要手填。

## 串联支路用 `chain()`：不要自己算坐标

引脚→电阻→LED→GND 这类结构，**手算偏移必然出事** —— `x0+110`、`rx+21`、
`lx+13` 这些数字里，只要有一个错几像素，线就接不上。而且极向一改（比如
`direction=-1` 时阳极跑到另一侧），所有偏移就全错了。

```python
r = chain(d, ends["PA0"], [
    ("R", resistor, dict(w=42, h=15), "1K"),
    ("L", led,      dict(s=13, direction=1), "LED1"),
], to_ground=True)

r["ends"]["L"]      # 该元件右侧端子, 供后续引用
r["terms"]["L"]     # 该元件全部端子
```

**端点由 `terminals()` 算出来，不是填出来的** —— so「线从元件本体上穿过去把
它短路」这类错误在结构上不可能发生。手写版踩过：电阻的线接到 LED 阳极
（`lx+13`）再横穿本体，把 LED 短路了；`direction` 一改就必然再踩一次。

`step` 是**净间距**（两个端子之间），不是中心距。连到**母线**的那一段
`chain()` 管不到，自己补 `line()` + `junction()`。

## 标注不要手填坐标：用 `place()`

元件数值/型号的标注，**写死偏移必然出事** —— 同一个偏移在 R1 右边是空的
（干净），到 R4 就压在集电极引线上。试过「放本体正上方」「放左侧」，
都只是把冲突换个地方。

```python
d.add(resistor(430, 262, vertical=True))
place(d, 430, 262, "33K")        # 只登记, 不立刻画
...                              # 继续画剩下的走线
d.save("out.svg")                # save() 自动 flush, 不用手动调
```

它按 `prefer`（`right`/`left`）的顺序试候选位，选第一个不压线、不压字的；
四周都满了才退到本体下方。

**必须整张图画完再落位** —— 登记时该元件的下游导线往往还没画（比如 R2 到
GND 那段），那时判碰撞会漏判，挑出一个稍后被导线穿过的位置。`Doc.save()`
会在正确时机自动调 `flush()`，所以正常用法下不用管这件事。

## 符号速查

**符号签名、端子坐标、包围盒尺寸一律查 `references/quickref.md`** ——
那张表是从 `terminals()` / `_needs()` 反射生成的实测值，`selftest.py` 会断言
它与代码一致，所以不可能过期。

这里**不再重复一遍**：手抄的副本没有这道保障，本技能上一版就因为手写的端子表
过期，让一排电阻整片误报「器件重叠」。

只需要记住一条：**接线端点来自 `terminals()` 或符号返回值，不要手填偏移**
（`mcu_block` 返回的 `ends` 是引脚引线的外侧端点；`npn` 返回 `{"b","c","e"}`）。

**手填偏移是本技能几乎所有缺陷的共同成因**：写 `yL+70` 而实际端子在 `yL+65`、
写 `XQ+9` 而实际端子在 `XQ+22` —— 图上只差几像素，看着接上了，实际是断的。

## ⚠️ 电气陷阱：这几条会让你**短路而不自知**

这些错误 `verify()` 全部返回 0，肉眼也全部看不出来。**画的时候就按这几条避坑**，
画完再用 `check_net.py` 兜底。

**完整清单（7 条）在 `references/quickref.md` 第 5 节。** 这里只重复最常犯的
三条 —— 它们是"手写坐标"必然导致的，用 `chain()`/`bus_net()` 可以结构性规避：

1. **竖直元件（`resistor`/`capacitor`, `vertical=True`）本体没有内置引线。**
   本体占 `cy±21`（电阻）/ `cy±19`（电容）。引线**只能从本体上下边缘起笔**，
   绝不能从上方一路画到下方 —— 那段线从元件身上穿过去了，等于用导线把它短路。

2. **`npn()` 的 `c` 与 `e` 在同一个 x（`cx+s`）上。**
   两路都直接竖直走线会**叠成一条从 VCC 直通 GND 的导体**，三极管被整体短路。
   必须把两路横向错开。

3. **引线端点必须精确落在端子上** —— 差 1px 就是断路；**交叉处没有
   `junction()` 就不算相连**，该连的地方一定要打点。

## 排版经验（都是实际踩出来的）

1. **水平导线间距 ≥ 18px**，复杂图建议 ≥ 34px。低于这个数，两条平行线会被看成一个连接点。
2. **支路间距要算上"器件标签"的高度，不只是符号本身**。`led` 符号本体约 26px 高，
   但下方还有一行 `LED1` 标签，**整框 69px** —— 曾有一版流水灯行距给了 60px，
   于是每颗 LED 的标签都塞进了下一颗的框里，自检器报了 4 处重叠。
   加宽到 76px 才干净。**排多路同构支路时，先想清楚一路"从最顶上到最底下"占多少。**
3. **两个相邻支路的间距 < 上一路的"元件抬升高度 + 连接下探深度"就会撞**。
   实测一路按键支路占 117px（按键标签 y-44 到地符号 y+73），间距只给 110px 就压上了。
4. **文字不要压在长导线上**。引脚名用 `mcu_block` 默认的 `label_above=True`
   （画在引线上方）。只有确认右边不再拉线时才用 `False`。
5. **跨功能块的信号用网络标签**（`marker(x, y, 1)` / 虚线），不要拉长实线穿过去 ——
   既难看又容易误读。例如 `PD0 --虚线--> 晶振 C`。
6. **一组支路的回流线不要横穿其他支路**。实测三路 NPN 的发射极
   原本各自先下探 42px 再横着拉回右侧 GND 母线，那段横线贴着下面几路的基极行过去，
   看上去像"Q1 的发射极接到了 Q2 的基极"。改成在晶体管右侧开一条**专用竖直通道**，
   三路汇到一根上，再由最下面一路横拉出去。
7. **MCU 方框里的第一行引脚要躲开型号副标题**。`mcu_block` 把副标题画在 `y+46`，
   引脚行如果从 `y+40` 开始，行内注释（靠右对齐、占满左侧宽度）就会和它叠上。
   首行从 `y+62` 起。
8. **改完一定重跑 `verify`**。手工调坐标极易修好一处、碰坏另一处。
   改一轮跑一轮，比一口气改五处再看要好定位得多。

## 改了符号几何之后：重新标定

`_needs()` 里的尺寸是**量出来的**（`scripts/measure_symbols.py`），不是估的。
如果你改了符号的绘制代码（加标签、拉长箭头、改字号），必须重跑标定并同步
`_needs()`，否则：

- 尺寸**估大**了 → 相邻支路整片误报"器件重叠"（实测：行距 60px、估成 62px，
  报了 4 处假问题）
- 尺寸**估小**了 → 真正画出画布的器件漏检

```bash
python .agents/skills/stm32-wiring-diagram/scripts/measure_symbols.py --check
```

报 `[小]` 就是该改大了，它会把实测值直接列出来。

## 完整原理图怎么组织

一张完整原理图按功能分块，每块一个底色外框 + 标题：

- **电源**：输入端子、稳压、各路电压去向
- **主控 MCU**：型号、封装、全部相关引脚
- **时钟**：晶振 + 负载电容 + 分频倍频标注
- **复位与调试**：NRST 电路、SWD 排针
- **驱动电路**：功率级（三极管/MOS/驱动芯片）+ 负载
- **控制电路**：按键/编码器/传感器

布局用网格，块之间留出**走线通道**（≥60px）。先定各块的矩形，再把元件放进块内，
不要边画边试——那样一定会重叠。

## 交付前检查清单

**两道门都必须过，缺一不算交付。**

排版门：

- [ ] `check_svg.py` 返回 **0**（文字重叠/压线/水平线过近/**竖线过近**/器件越界/器件重叠/**文字越界** 七类）
- [ ] 已渲染 PNG 用肉眼确认过**布局**：成排、不交叉、标注不错位

电气门：

- [ ] `check_net.py` 返回 **0**（短路/旁路/穿体/悬空/接错/畸形/飘端子/孤标签 八类）
- [ ] 自绘器件都写了 `declare()`（端子 + 本体 + `expect`）
- [ ] 功能网已逐个核对过（分压点真的汇集了该汇集的元件？集电极网含负载与输出耦合？）
      —— 用 `check_net.py --show-nets` 看网表成员
- [ ] **方向性器件逐个核对过**（LED/续流管/电解电容/三极管/稳压管的极性）
      —— **这一步工具查不出**，必须照"核对方向性器件"那节的表看网表

内容与交付：

- [ ] 引脚全部来自 `read_config` 或源码，**没有手抄**
- [ ] 极性描述与实际配置一致（推挽/开漏、三极管是否反相）
- [ ] 源码注释与实际配置矛盾时，已在图中指出
- [ ] **脚本跑完没报错**（脚本中途崩溃时 `save()` 可能已经把旧版图写盘了，
      别对着旧图下判断）
- [ ] 图的路径与脚本都在**对应的工程目录**下，`.svg` 可用浏览器打开

> ⚠️ **不要**把"用肉眼看一遍确认没有电气错误"当检查项 —— 那是无效手段，
> 短路和旁路在图上就是一根普通直线。要么跑 `check_net.py`，要么明确承认没查。
>
> ⚠️ 反过来也要记住：**门禁过了 ≠ 电路对了**。它查连通，不查极性/方向，
> 也不认识你没 `declare()` 的自绘器件。
>
> ⚠️ **更要注意：连着的东西对不对，门禁也判断不了。** 实测过一次 —— 一条
> 横贯全图的 +V 母线把 3.3V 域和 5V 域短在一起，两道门都报 0，因为图
> **忠实地实现了错误的意图**。所以画完**必须打印网表逐条核对**：
> `check_net.py --show-nets`，确认每个网络里装的是它该装的东西
> （尤其：电源域有没有混在一起）。

### 电源符号接在导线**中点**也要连通

历史 bug：接在导线中点的 `vcc`/`ground`/`power_in` 曾经**不与该导线连通**
（只有当它落在某个导线**端点**上时才间接连上）。后果极其危险 ——
中点接的地被静默孤立，而检查器报 0 问题。已修，并有回归用例 C8/D11。
如果你画图时发现"电源符号明明压在线上却没连上"，先确认技能版本是最新的。

## 常见返工

| 自检报的 | 通常怎么改 |
|---|---|
| `文字重叠` X <-> Y | 拉开两者间距；或把注释移到不同的行 |
| `文字压横线/竖线` | 标签上移/侧移，或用 `mcu_block(label_above=True)` |
| `水平线过近` | 加大行距（同构支路尤其要注意"符号+标签"的总高） |
| `超出画布` | 加高/加宽画布，或把元素整体内移 |
| `器件重叠` | 支路间距不够，或某个符号的 `_needs()` 该重新标定 |
| `短路` | 电源与地之间被某根线连起来了。顺着网表成员找出那根线 |
| `旁路` | 该元件两端接在同一网。看是不是有引线从它身上穿过去了 |
| `穿体` | 引线跨越了元件本体的 y 区间。改成从本体边缘起笔 |
| `悬空` | 引线端点没落在端子上。用 `terminals()` 取准确坐标，别手填偏移 |
| `接错` | 自绘器件的 `expect` 没兑现。顺着报错里的两个网名找那根线（常见：接到相邻的节点上、差几 px 没搭上电源符号） |

## 数值标注怎么落位（别写死偏移）

元件数值/型号的标注，**同一套偏移在不同元件上会有的干净、有的压线**
（R1 右边是空的，R4 右边紧挨着集电极引线）。写死偏移只会把冲突换个地方。

**用 `place()` 登记、整图画完后统一落位** —— 用法见前面
「标注不要手填坐标：用 `place()`」一节。

> 历史上曾有脚本自带一套本地实现（`rval()` / `flush_values()`，
> 登记在 `d._pending` 上），**现已并回库里**，那两个函数不存在了。
> 所有脚本一律用 `place()` / `flush()`。
