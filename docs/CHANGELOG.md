# 修复历史

本文件记录这套工具的检查能力是怎么一步步补上来的，以及**每一类检查是在哪张
真实的错误图上被抓出来的**。保留这些是因为它们解释了为什么某些检查长这样 ——
每一条约束背后都有一次真实的踩坑。

---

## 起点：只有排版检查

最初 `check_svg.py` 只查五类排版问题（文字重叠、文字压线、平行线过近、
器件越界、器件重叠）。它做得扎实，在一次真实会话里抓到了 6 处排版错误。

**但所有致命错误（会烧片子 / 电路不工作）全部是电气错误，全部逃过了这道门，
也逃过了肉眼。** 短路和"元件被旁路"在图上就是一根普通的直线 —— 线条笔直、
元件规整、不压字不重叠，排版检查给满分，人眼也给满分。**不存在"看着别扭"这个信号。**

于是补上了第二道门：把图还原成网表做连通性分析。

### 网表检查上线时当场抓出的 7 处真实缺陷

这些图此前排版检查全是 0，也都被人眼看过了：

- 集电极引线差 13px 悬空
- 每个耦合电容的两端各差 8px
- 晶振两极差 34px 全断
- 若干 LED 的引线横穿本体把 LED 短路

---

## 连通性判定的核心规则

> **端点相接才算连接；中途交叉不算** —— 除非交点处有 `junction()` 圆点。

少了这条，两条只是视觉上交叉的导线会被判成连通，于是报出一堆"分压网络短路"
的假阳性。**假阳性比不查还糟** —— 它会让使用者不再信任这个工具。

回归测试 `D1`（纯交叉不能连）和 `D2`（有 junction 才能连）就是钉这条的。

## 逐类检查的来源

| 检查 | 怎么发现的 |
|---|---|
| **短路** / **旁路** / **穿体** | 设计网表分析时直接想到的三类 |
| **悬空** | 上面那 7 处缺陷；"差几像素"是最常见的错误 |
| **接错** | `declare(expect=)` 上线时，抓出一处**前四类全漏掉**的缺陷 —— 续流管与继电器线圈那一整块没接到 +5V（电源母线画在 y=122，`vcc` 符号接点在 y=120，差 2px） |
| **畸形线段** | 一个子 agent 报告"符号被非确定性丢弃"。复现 4 次都不成立，真正原因是**它自己把颜色常量 `WIRE` 当成坐标用**，写出了 `<line x1="#37474f">` —— 正则静默丢弃了这条线，然后报出一片假的悬空/旁路。它的连锁反应最容易埋掉真病因，所以单独列一类并排在输出最前面 |
| **飘端子** | 一次真实交付里，继电器线圈声明端子跨 `cx±38`，但画弧的代码只跨 `cx±21` —— 两个端子各悬在图形外 17px。导线**确实**接在声明的端点上（连通性完美），但那里什么都没有，图上看着像"线圈两端没接线" |
| **孤标签** | 文档一直说"同号 `marker()` 表示电气相连"，但 `analyze()` 根本不认它。修好并网逻辑后，顺带补了"落了单的标签"检查 |
| **文字超出画布** | 第 4 类只查登记过的器件，裸 `<text>` 跑到画布外会被渲染器静默裁掉 |
| **平行竖线过近** | 与"平行水平线过近"同理，原来只查水平方向 |

## 修掉的自身缺陷（都是测试或子 agent 发现的）

- **`Doc.add()` 对元组抛 TypeError** —— `d.add(npn(...))` 是最自然的写法，
  而 5 个符号返回 `(svg, 端点)`。官方最小示例自己就是这种写法，却被堵死。
- **`chain()` 拒绝自绘符号** —— `terminals()` 是没有扩展点的 if-elif 链。
  用继电器/光敏管的电路只能手算坐标，正是"差几像素"的根源。补了 `register_symbol()`。
- **`chain()`/`bus_net()` 不给自绘符号 `declare()`** —— 于是自绘几何被当成真导线，
  而且检查器看不见它。
- **`bus_net()` 的 `up` 支路落点错** —— 算出了端子偏移又丢弃，写成 `cy = tap - 68`。
  位置比一变偏差就变。
- **`mcu_block` 包围盒不含引脚名** —— 左右都挂引脚名的 MCU，最外侧标签落在登记框外。
- **`place()` 会挑到画布外的位置** —— `prefer="left"` 时把注释放到 x=58，而左边距是 40，
  整条注释被裁掉；而且因为没压线没压字，它以为挑到了好位置。
- **接在导线中点的电源符号被静默孤立（最危险的一类漏检）** —— 一个 `continue`
  跳过了线段合并，于是"中点接的地"不与该导线连通，而检查器报 0 问题。**这意味着
  一个真实的 VCC-GND 短路可能被漏掉。**
- **`[飘端子]` 的第一版用包围盒判定** —— 抓不到包围盒内部的空洞。改成"到最近绘制
  特征的距离"后，一个 U 形符号端子在内部空洞里（距 50px）也能报出来。

## 这一过程中确立的原则

1. **能结构性避免的错误，不靠检查去发现。** 布局工具（`chain`/`bus_net`/`link`）
   从符号自己的端子表算坐标，人手不接触数字。实测：改用这些工具后，手写的
   `d.add(line(...))` 从 93 处降到 0，数字字面量从约 435 个降到 29 个。
2. **检查器必须能抓"看着没问题"的错误。**
3. **假阳性比不查更糟** —— 所以每个检查都配"必须报"和"不能报"两类用例。
4. **文档必须从代码生成。** 手写的接口表会过期：曾经一份手写的端子表数据有误，
   让一排电阻整片误报"器件重叠"。现在 `quickref.md` 由反射生成，
   测试断言它与代码一致。
5. **门禁查的是"连通"，不是"接对"。** 这条要反复讲，因为它是工具能力的真实边界。

---

## 已知边界（工具查不出，必须人工核对）

- **极性 / 方向**：LED 阳极、电解电容正负、续流管方向、稳压管反接 ——
  两根线都接在正确端子上，连通性完美，任何检查都不报。
  必须用 `--show-nets` 打网表逐个看方向性器件两端落在哪个网。
- **连着的东西对不对**：图可能**忠实实现了错误的意图**。实测过一次 ——
  一条横贯全图的 +V 母线把 3.3V 域和 5V 域短在一起，两道门都报 0。
- **自绘符号端子声明与实际绘制是否一致**：`[飘端子]` 只抓"端子离图形太远"，
  抓不到"端子落在图形内、但落在错的那一段上"。
- **参数取值**：静态工作点、增益、元件数值。
- `net2svg()` 只支持单主干；分支节点会用 `bus_net()`（前者已改为明确报错并指路）。
